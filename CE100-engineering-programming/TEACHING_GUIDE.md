# 교수자 가이드 · 코딩 AI 사용과 결과 검토

## 수업 목표와 운영

학생이 기본 원리를 설명하고, 문제를 입력·출력·조건으로 바꾸며, AI의 제안을 시험과 근거로 검토하게 합니다. 실습에서는 문법을 찾아보는 것을 허용하고, 답을 얻은 뒤 판단 근거를 설명하는 활동까지 진행합니다.

한 노트북의 핵심 활동은 약 40~50분을 예상합니다. 이는 수업 운영을 위한 제안이며 학생 수준에 맞게 조절합니다. 같은 주차에 노트북이 두 개면 시간을 나누거나 두 차시에 배치합니다.

| 활동 | 권장 시간 | 관찰할 것 |
| --- | --- | --- |
| 원리와 실행 전 예측 | 8분 | 결과의 이유를 설명하는가? |
| 예제 실행·조건 변경 | 10분 | 바꾸기 전 예상과 실행 후 결과를 비교하는가? |
| 작은 기능 완성·공개 점검 | 12분 | 입력·출력·실패 계약을 만족하는가? |
| 가상/실제 AI 답변 검토·수정 요청 | 10분 | 반례와 구체적인 지시가 있는가? |
| 새로운 조건 적용·마무리 | 5분 | 무엇을 추가로 질문해야 하는지 아는가? |

개념에 익숙하지 않은 학생에게는 입력 두 개를 손으로 추적하게 하고, 익숙한 학생에게는 새 반례·변경된 계약·선택 확장을 부여합니다. 교사는 실행 결과를 보여 주기 전에 예측을 짝과 비교하도록 안내할 수 있습니다.

## 학습 증거 점검 기준 예시

아래 다섯 영역을 각각 0~2점으로 관찰할 수 있습니다. 실제 성적 반영 여부와 비중은 교수자가 정합니다.

| 영역 | 0점 | 1점 | 2점 |
| --- | --- | --- | --- |
| 원리 이해 | 코드의 역할을 설명하지 못함 | 동작은 설명하나 자료형·단위·가정이 빠짐 | 작은 입력을 추적하며 핵심 원리와 조건을 설명 |
| 요구사항·AI 지시 | 목적만 제시 | 입력·출력은 있으나 경계·실패 정책 누락 | 구체적 예·계약·수정 지시를 명시 |
| 구현·실험 | 미완료 또는 재실행만 함 | 공개 점검은 통과하나 변경 실험의 이유 부족 | 계약을 만족하고 입력 변경의 효과를 설명 |
| 결과 검토 | 실행 성공만 근거로 제시 | 공개 시험 결과만 제시 | 독립 기대값을 가진 새 반례와 실제 결과를 제시 |
| 판단·전이 | AI 제안을 근거 없이 채택 | 수정 이유 또는 한계만 설명 | 채택 판단·한계·새 요구사항의 추가 질문을 연결 |

AI 접근 여부나 긴 코드 작성량 자체는 위 점수의 근거가 아닙니다. 가상 답변 검토로도 동일한 판단 근거를 제출할 수 있습니다. 학생의 추가 시험은 공개 시험을 그대로 반복한 것인지 확인합니다.
